# Briefs S6-F, S6-E and S6-S: packages, configurations, and what is left before G1

Read `briefs/COMMON-B.md` first, then the brief of the same track of S0 (`s0-front.md` or
`s0-engine.md`), and `briefs/s1.md` to `s5.md` where you need their ownership and rules. State
files: `scratch/rewrite/b1/s6-front/STATE.md`, `b1/s6-engine/STATE.md` and `b1/solve/STATE.md`
(S6-S adds a section to the last). Read the STATE files of your track in S5 for what it built.

S6 is the last slice before gate G1, at which every worked example of the spec runs from source,
and so does one file with every construct. So beside the front end of S6, the engine finishes what
earlier slices left refused (S6-E), and the solve library takes fair sharing to full scale (S6-S).
The three tracks write different directories.

## The subset of S6

From `spec.md`: "How templates compose into a run" and "A run produces one trajectory"; the
scenario line. From `g0-decisions.md`: D9 (the scenario owns comparisons and publication; one run
is one effective configuration, one mode, one seed, one set of choices) and D2 (overrides follow the
declared type). From `rulings.md`: R-A5-01 to R-A5-07, with their text in
`scratch/rewrite/a5/FINDINGS.md`: the precedence external edit, option, `change`, instance line of a
variant, template, with conflicts as errors; `options` and `runs:` with full paths, an option sets
only an `input`; a number or a yes/no that an option or a `change` sets needs a record; runs and
comparisons live outside the model (`brief.toml`); an instance replaces a template formula with
`m = formula(E)`.

## S6-F: the front end

You own what S5-F owned, and `napkin/schema/` and `napkin/model/runs.py`; in this slice only you may
change `napkin/program/` and `tests/program/`. `use`, `variant`, `change`, options, named runs and
the edit document (`napkin/schema/edits.schema.json`) give one run configuration over one program:
the `Configuration` of `napkin/program/config.py` (inputs, start values, mode, seed, controllers,
picks), and a program of its own where a variant or a `change` changes the model. `model_hash`
reads the declared model and the key of a stored run reads the program and the configuration, so a
change of a label moves neither; `LANGUAGE_VERSION` goes up. The compile API takes a run's name and
an edit document; the command line stays the main session's (it adds the flags at the join).

Port the PORT-FRONT rows of S6 in `scratch/rewrite/tests-triage.csv`: `tests/model/`
`test_admission_scope.py`, `test_compiled_views.py`, `test_identity.py`, `test_meaning.py`,
`test_modules.py`, `test_orders_and_options.py`, `test_packages.py`, `test_runs.py`, and
`tests/engine/` `test_combinations.py`, `test_options_and_runs.py`,
`test_options_runs_closed_forms.py` (as front-end tests of the configuration; delete the old
files); `tests/engine/test_binary_controls.py` (its edit cases; delete it after). List each file,
and what of it waits for stage C.

The example of the join: one package with a variant, two options and an edit, whose configuration
and program you assert from source. Last, if usage allows: `tests/acceptance/test_every_construct.py`
anew, one model with every construct of the language from source to `napkin.engine.run`, its values
worked by hand; a construct that the engine still refuses is listed in the file's docstring, not
skipped silently.

## S6-E: the engine, what is left before G1

You own what S5-E owned, except `napkin/engine/solve/` and `tests/engine/solve/` (S6-S) and the
four files of `tests/engine/` that S6-F ports (the three of options and runs, and `test_binary_controls.py`). What is still refused (`b1/s5-engine/STATE.md`,
`PLAN.md` under S5):
- in a stage, the assignment of a formula or a collection, and keyed reads of moving values and
  keys (refused "(S4)");
- a setting that reads a moving rate of another connected set (refused with no stage);
- a priority endpoint with a request inside a declared solver (refused by name): decide from the
  spec whether the language allows it, and run it or keep the refusal with the spec's reason.

Run each, with tests against closed forms and the oracle. Then port the cases of
`tests/engine/test_runtime.py` and `test_timeline.py` that are not events, and say what of each
waits for stage C. The engine's side of S6, if any: a configuration's inputs and start values, a
variant's program. At the end nothing may be refused naming a slice of B; what the first version
leaves out is refused with the spec's reason.

## S6-S: fair sharing at full scale

You own `napkin/engine/solve/`, `tests/engine/solve/` and `scratch/rewrite/b1/solve/`. The program
of A3's network at 30,000 places (`scratch/rewrite/b1/s5-engine/bench.py`) stops at 0 h with
"numerical in fair sharing, tier 0: HiGHS ended with the status kUnknown", and the library's own
`scratch/rewrite/b1/solve/bench.py fair --share 1.0` fails the same way at that size; 3,000 places
solve. Find why. Mend it in the library if you can without another answer (D0, R-A3-*: a fallback may
be slower, never different); else measure the largest size that solves, at the shares the bench
offers, and make the failure say what the library could not do and at what size. Tests use arrays
and exact fractions, as `tests/engine/solve/` does. Then run the S5 measurement again, once, and
give its times.
