# Brief A2: reference semantics

Folder: `scratch/rewrite/a2/`. Read `briefs/COMMON.md` first.

## Question

What exactly happens at one time, and between two times? The spec gives the rules in prose and
leaves some open. Write them as a small interpreter that anyone can read, make it reproduce every
worked number of the spec, and rule on what is open.

The interpreter is kept after the prototypes: it becomes the oracle of the engine's tests. So keep
two things apart: a plain description of a model (data classes: templates, fields, stores, flows,
events with stages, triggers, solvers), and the code that runs a description. A later step makes it
read the real program records in place of your data classes.

## Method

Folder `ref/`: a Python package. No parser: a model is built in Python.

- **Arithmetic** in exact fractions (`fractions.Fraction`) wherever it can be.
- **Between two moments** every rate is constant, or a known polynomial in time (the ramp example
  of the spec has a rate that is linear in time). Integrate these exactly. Say what you do not
  cover.
- **The next moment** is the earliest of: a stage that is due; the first contact of a trigger or of
  an `until` with its inclusive boundary; a store that reaches a bound; a key time of an `.at(t)`
  read; the horizon.
- **At a time**, rounds as the spec says: the due stages commit in a deterministic order; writes,
  starts and the flows that join or leave are registered; the rates and each affected solver settle
  once; the conditions of triggers are read; new consequences at the same time start a further
  round.
- **The rates at a moment** follow the selection order of the spec, by brute force:
  1. the hard conditions: domains, capacities, the balance of a store on a bound, each declared
     constraint;
  2. each written objective in order, each kept at its optimum (`scipy.optimize.linprog`);
  3. inherited fair sharing: in each priority tier, maximize the smallest served fraction, then the
     next;
  4. the least squared distance of the flows to their requests, then of the other unknowns to their
     reference values. A linear program cannot give this rank: for `x + y == 1` with both targets
     zero the answer is (1/2, 1/2), and a linear solver may return (1, 0). Write an exact
     calculation of your own: for a small problem, try each set of active inequality rows, solve
     the conditions of the least distance in fractions, and keep the one feasible answer.
- **Run modes**: `median` and `sampled`, with a key for each draw so that a replay gives the same
  draws.

## Rulings that you owe

The order of simultaneous starts, and of the members of a start on a collection. Conflicting
writes from two stages of one round. Reset cycles. Setup order. `none` in arithmetic, in a
comparison and in a reduction. `min` and `max` over nothing. `elapsed` after several writes in one
stage, and a read with zero delay inside a stage. What stays readable on a finished occurrence,
also its local store. Whether a saved reference to an occurrence pins it. A flow with legs that two
endpoints rank differently. The budget for occurrences that never finish, and its message. Where a
human choice pauses when the stage has queued a start. Where an `assert` on state is checked. An
invalid history read that a report asks for: it must not change the run. The key of each draw. How
an opening balance from outside is recorded.

For each, the example must be one on which your rule and its alternative give different results,
and the interpreter must run it.
