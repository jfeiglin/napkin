# Notation that the spec shows only inline, one piece on each line, written by hand.
#
#   kind <tab> line of spec.md <tab> notation
#
# The kind says where the piece stands, and so which part of the parser reads it:
#   expression   a value
#   type         what stands after the colon of a declaration
#   range        the closed interval of a declaration, read after `in`
#   declaration  a line of the body of an entity
#   setup        a line at the top level of a file
#   step         a line of the body of an event (the block under it can be missing here)
#   statement    a line of a stage
#   trigger      a line of the body of a trigger (it is read under `when true:`)
#   objective    a line of the `objective:` section of a solver
#
# A capital letter that stands for "some duration" or "some condition" in the spec (`D`, `C`, `T`)
# is kept as written: the parser reads it as a member of an enum or as a type name.
# A line marked `derived` is not written in the spec as it stands: the spec names a member
# (`.mean`) or half a line (`SOURCE -> SINK`), and the line here gives it a receiver or a name.
